# Whittle Phase 04A · FreeCAD profile study

Reference revision is FreeCAD 1.1.0, commit `34a9716668b1ddeb55b914f1c5be644826bdbbbf`. The comparison traces the source and checks Whittle behavior through its native sketch, Manufacturing setup, tool position, viewport, and CAM document workflow. [FreeCAD release](https://github.com/FreeCAD/FreeCAD/releases/tag/1.1.0) · [Pinned source](https://github.com/FreeCAD/FreeCAD/tree/34a9716668b1ddeb55b914f1c5be644826bdbbbf)

### Source trace and licensing

- `Profile.py` derives from the Area operation. It uses FreeCAD, Path, Part, Draft geometry, NumPy, and PySide. The Area base passes depth heights to `Path.Area.makeSections` and feeds the result to `Path.fromShapes`. The separate open-wire path sets a direction-specific start to keep travel from being reversed by the path builder. Both Python files and the Lead In/Out dressup carry LGPL-2.1-or-later headers. [Profile.py](https://github.com/FreeCAD/FreeCAD/blob/34a9716668b1ddeb55b914f1c5be644826bdbbbf/src/Mod/CAM/Path/Op/Profile.py) · [Area.py](https://github.com/FreeCAD/FreeCAD/blob/34a9716668b1ddeb55b914f1c5be644826bdbbbf/src/Mod/CAM/Path/Op/Area.py) · [LeadInOut.py](https://github.com/FreeCAD/FreeCAD/blob/34a9716668b1ddeb55b914f1c5be644826bdbbbf/src/Mod/CAM/Path/Dressup/Gui/LeadInOut.py)
- The LGPL-2.1-or-later native `App/Area.cpp` uses Open CASCADE shapes, Boost, and libarea. Its offset pipeline calls `CArea::OffsetWithClipper` and also contains an optionally compiled libarea offset branch. The BSD-3-Clause `AreaClipper.cpp` scales and converts curves to integer polygons, uses `ClipperOffset` with join and end rules, and reconstructs and reorders output curves. The bundled `clipper.hpp` is Clipper 6.4.2 under BSL-1.0. The build links the Path module to Part, FreeCADApp, and area-native, and links area-native to FreeCAD Import. The separate Python area wrapper also has build-time Python dependencies. - The changes are original TypeScript in the Whittle project, which declares MPL-2.0. No upstream code or dependency was imported. A future native integration should assess each file and transitive dependency alongside the intended distribution and linkage.

### Limits and next candidates

- Clearance is measured above the selected sketch. The user chooses a height that clears the stock and fixtures, and a plunge location suitable for the tool. The stock, shank, holder, and fixtures are outside the geometric interference check. The increment provides CAM preview and playback. Machine postprocessing and validation are outside this contour workflow.
- This increment supports one chain, a fixed seam for closed contours, straight tangent leads, and one radial offset per depth. Arc leads, adjustable seams, finishing allowance, topology-changing offsets, islands, and stock-aware linking remain open.
- For pocketing, use `PocketShape.py` and native `makePocket` as references for boundary preparation, nested regions, and stepover. Evaluate a separately licensed planar Boolean and offset library with explicit hole topology and tolerance. Reuse the setup frame, depth schedule, clearance sequencing, and neutral motions as pocket fixtures expose shared needs. [PocketShape.py](https://github.com/FreeCAD/FreeCAD/blob/34a9716668b1ddeb55b914f1c5be644826bdbbbf/src/Mod/CAM/Path/Op/PocketShape.py) · [Native Area](https://github.com/FreeCAD/FreeCAD/blob/34a9716668b1ddeb55b914f1c5be644826bdbbbf/src/Mod/CAM/App/Area.cpp)
- For adaptive, the pinned `Adaptive2d::Execute` accepts stock, boundary, and cleared coordinate paths and returns classified paths. Its LGPL-2.1-or-later solver uses the bundled Clipper 6 header and implementation at this revision. A standalone C++/WASM feasibility study can test the geometry and motion boundary once distribution obligations are assessed.
